# Pi Pet

English | [简体中文](README.zh-CN.md)

A desktop pet for Omarchy that watches **pi** and talks to you in its own voice.

This is a pi-only fork of [agent-pet](https://github.com/chthollyphile/agent-pet) / [dsh-pet](https://github.com/PC2005-cloud/dsh-pet).
Everything built for Claude Code, Codex, rate-limit usage and step summarising has been removed: one agent, one event
source, one model.

## What it does

- **Pet behaviour** — idling, random actions, walking, click reactions, and physics-based dragging and throwing.
- **Live work status** — six states (thinking, working, reading results, waiting on you, done, error) driven by a small
  pi extension, together with the project name, the running tool and command, and context-window usage.
- **Murmurs** — every few minutes she says one short line, generated by your own `pi` and your own model. Streamed to
  the screen, with a visible thinking phase.
- **Chat** — right-click her and pick Chat to talk. Replies stream into the same bubble and go through the same session
  as the murmurs, so she remembers the conversation (and `agent-pet forget` wipes it).
- **Attention alerts** — a desktop notification when pi needs you, finishes, or fails. Sent only while the terminal is
  unfocused, and carrying nothing but the agent name and state.

## Requirements

- Omarchy 4
- `qt6-imageformats` for WebP decoding; run `omarchy-restart-shell` after installing it
- `pi` on `PATH`
- `notify-send` for desktop notifications

No `jq`, `socat`, `python`, or rate-limit collector is involved.

## Install

```bash
omarchy plugin add <this-repo-url> --enable
```

That is the whole installation. Nothing is written into `~/.pi/agent/extensions/`, because pi loads everything in that
directory into **every** session — including the ones you work in. The reporter is imported explicitly instead:

```bash
# try it once
pi -e ~/.config/omarchy/plugins/local.pi-pet/ext/agent-pet-pi.ts

# or make it permanent: `pi-pet` reports to the pet, a plain `pi` never loads it
alias pi-pet='pi -e ~/.config/omarchy/plugins/local.pi-pet/ext/agent-pet-pi.ts'
```

Restart pi after adding the alias (`pi` cannot hot-load extensions). If you installed an earlier build into
`~/.pi/agent/extensions/agent-pet-pi.ts`, delete that symlink; it is no longer used.

## Configuration

Defaults live in `assets/config.json`. Put overrides in `$XDG_CONFIG_HOME/agent-pet/config.jsonc`
(`~/.config/agent-pet/config.jsonc` by default); comments are allowed and the file reloads on save. Runtime state follows
`XDG_STATE_HOME` the same way.

Merging is **deep**: objects merge key by key, arrays are replaced whole, and `null` deletes a key so it falls back to
the built-in default. A fully commented, drop-in example lives at
[`examples/config.jsonc`](examples/config.jsonc) — copy it and edit:

```bash
cp examples/config.jsonc ~/.config/agent-pet/config.jsonc
# set murmur.model, then edit the rest to taste
```

### Murmurs

```jsonc
"murmur": {
  "enabled": false,              // no model call at all while false
  "model": "",                   // required, "provider/model"; empty disables murmurs and chat
  "provider": "",                // only needed to disambiguate identical model ids
  "thinking": "low",             // off | minimal | low | medium | high | xhigh | max
  "session": "agent-pet",        // persistent session id; empty = stateless per request
  "extensions": [],              // extra extension paths; relative ones resolve under the config dir
  "tools": ["pet_state"],        // tool allowlist; an empty array means no tools at all
  "intervalSec": 600,
  "stream": true,                // false falls back to `--mode text`, one-shot output
  "typewriterCps": 30,           // 0 prints deltas as they arrive
  "showThinking": true,          // show the grey "thinking" line while she composes
  "firstTokenTimeoutSec": 15,
  "timeoutSec": 120
}
```

### Optional: web access for the pet

She can look things up with [pi-web-access](https://www.npmjs.com/package/pi-web-access) if you install it into her own
extension directory (your `~/.pi/agent/extensions/` is never touched):

```bash
bin/agent-pet-web-access      # npm-installs it under ~/.config/agent-pet/ext/ and prints the config lines
```

Then add to `murmur` in your config:

```jsonc
"extensions": ["ext/pi-web-access/node_modules/pi-web-access/dist/index.js"],
"tools": ["pet_state", "web_search", "fetch_content"]
```

`tools` is an allowlist: a tool you do not list cannot be called. Zero-config search works through Exa MCP; put provider
keys in `~/.pi/agent/web-search.json` to choose your own. Remove it again with `bin/agent-pet-web-access --uninstall`.

With an empty `model` nothing is ever spawned. There is no fallback to pi's default model, so a typo cannot quietly spend
your credits on something expensive.

## How the two pi processes relate

```
your pi (TUI), started with `-e`
  └─ ext/agent-pet-pi.ts        loaded only in sessions that ask for it, write-only
        │  unix socket  $XDG_RUNTIME_DIR/agent-pet/events.sock
        ▼
    omarchy-shell  (Service.qml in this plugin)
        ▲  one line back, but only for requests carrying an id
  └─ the pet's own pi (headless) started by bin/agent-pet-pi, strictly isolated
        └─ ext/pet.ts            the only tool it registers: pet_state
```

The two extension sets never see each other. The host one is loaded by `-e` in the sessions you choose and disabled in
the child with `--no-extensions`; the child one is loaded by explicit `-e` from the plugin directory and never lives in
your agent directory.

## The pet's own pi is sandboxed

`bin/agent-pet-pi` is the only place allowed to spawn a child pi, and every flag is hard-coded there:

- `--no-extensions` plus `-e` for the allowlisted paths only; `--no-mcp --no-skills --no-prompt-templates
  --no-context-files --no-approve`
- working directory pinned to `~/.local/state/agent-pet/pi-cwd`, an empty directory, so no project `.pi` can be found
- the tool surface is replaced wholesale by `murmur.tools`; an empty array becomes `-nt`
- inherited `PI_CODING_AGENT_DIR`, `PI_MODEL` and friends are stripped; `PI_TELEMETRY=0 PI_SKIP_VERSION_CHECK=1
  PI_OFFLINE=1` are forced (`PI_OFFLINE` only disables version checks and catalogue refreshes, not model requests)
- the prompt travels on stdin and the system prompt lives in `assets/persona.*.md`, so neither appears in process argv

What is limited is **what the model may call**, not what an extension may do. An extension listed in
`murmur.extensions` runs inside the pi process with your user's permissions. Add paths deliberately.

## IPC

```bash
omarchy-shell agent-pet state     # JSON: sessions, work status, context usage, speech state
omarchy-shell agent-pet say "Hello"
omarchy-shell agent-pet play <animation-name>   # names are listed in the right-click menu
omarchy-shell agent-pet murmur    # ask for one line right now
omarchy-shell agent-pet context   # context-window usage
omarchy-shell agent-pet toggle    # hide / show
omarchy-shell agent-pet reload    # reload config
omarchy-shell agent-pet forget    # clear her persistent session
```

## Runtime files

| Path | Description |
|---|---|
| `Service.qml` | Config, session state, speech, notifications, IPC |
| `ChatInput.qml` | The input box behind the Chat menu item |
| `Pi.qml` | Spawns the child pi, parses the event stream, drives the phase machine |
| `EventServer.qml` | Unix socket shared by both producers |
| `ext/agent-pet-pi.ts` | Host-side reporter, imported with `pi -e` |
| `ext/pet.ts` | Child-side `pet_state` tool |
| `bin/agent-pet-pi` | The single spawn point; isolation flags live here |
| `~/.local/state/agent-pet/pi-sessions/` | Her persistent session (`agent-pet forget` clears it) |
